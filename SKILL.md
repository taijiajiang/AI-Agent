## Path Management and Working Directory

There are two distinct path contexts in this workflow. They must never be confused.

### 1. Skill Directory

- The Skill Directory is the directory containing this `SKILL.md`.
- All referenced resource files and directories, including `Steps/`, `statistical methods/`, and `code templates/`, must be resolved relative to the Skill Directory.
- These paths must NOT be resolved relative to the current working directory.
- Before executing any workflow, identify the actual Skill Directory using the execution environment's available Skill metadata or file location.
- Do not assume that the current working directory is the Skill Directory.
- If the actual Skill Directory cannot be determined, stop and ask the user for clarification. Do not guess or silently substitute another directory.

### 2. Working Directory

- The Working Directory is the directory in which the Agent performs the current analysis task.
- Create the Python virtual environment in the Working Directory, not in the Skill Directory.
- Generated files, intermediate analysis results, and final QMD files should be saved in the Working Directory unless otherwise specified.
- Creating or activating a virtual environment must not change the path resolution rules for Skill resources.

### 3. Path Resolution Rules

For example, if the directory structure is:

```text
statistical-modeling/
├── SKILL.md
├── Steps/
├── statistical methods/
└── code templates/

analysis-project/
├── dataset.csv
└── .venv/
```

The following rules apply:

- `./Steps/data-cleaning.md` refers to `statistical-modeling/Steps/data-cleaning.md`.
- `./statistical methods/` refers to `statistical-modeling/statistical methods/`.

- The virtual environment belongs in `analysis-project/.venv/`.
- Analysis outputs belong in `analysis-project/`.

Always resolve Skill resource paths using the Skill Directory explicitly. Never rely on the process's current working directory to locate Skill resources.
